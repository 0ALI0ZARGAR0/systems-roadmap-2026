Domain 1: AI Systems Fluency

Your product relies on AI. This domain determines whether your categorization and retrieval pipelines actually deliver reliable results.

The Pipeline Mental Model

flowchart LR
    A["Raw Note Content"] -->|Chunking| B["Text Chunks"]
    B -->|Embedding| C["512d Matryoshka Vectors"]
    C -->|HNSW Graph Search| D["Top-K Candidates"]
    D -->|LLM Classifier| E["Folder / Topic Assignment"]

Failure Modes Across the 4 Stages

  1. Chunking: Naive character splitting cuts sentences mid-thought, destroying embedding semantic coherence. Use recursive character splitting (512 tokens with 10–15% overlap) respecting markdown headers.
  2. Embedding: Truncating Matryoshka embeddings to 512 dimensions trades ~1.5% recall for a 6x reduction in vector memory and compute. If classification accuracy drops, verify dimension indexing first.
  3. Retrieval (HNSW): As your vector store grows from 10K to 1M items, recall silently degrades unless you tune M (connections per node) and ef_search (search beam width).
  4. Classification: Underspecified prompts cause erratic folder assignment. Anchor prompt changes to automated evaluation sets.

Decision Matrix: Operational Signals

Observed SignalRoot CauseImmediate Remediation
Users manually reclassify notesClassification prompt or model degradationRun evaluation dataset; verify embedding consistency
Search returns irrelevant resultsHNSW recall drop or poor score cutoffLog P99 similarity scores; tune ef_search or re-index
Classification latency > 2sNATS queue backlog or upstream rate limitCheck queue consumer depth; add circuit breaker
Sudden token spend spikeLong document fragmented into 200+ chunksEnforce max_chunks_per_note ingestion limit

Project Anchor & Core Focus

  • Vault Milestone: Construct a golden test dataset (50 representative notes paired with verified target folders). Run regression evals on every prompt modification.
  • Rule of Thumb: Evals precede feature delivery. Never deploy classification or search changes without an automated eval harness.

Domain 2: Security Literacy for Builders (CRITICAL)

Security vulnerabilities in multi-tenant data layers are catastrophic. AI coding tools frequently introduce subtle authorization bypasses.

Mental Model: Horizontal Privilege Escalation

Authentication = "Who are you?"  --> Managed by Clerk (JWT verification)
Authorization  = "What can you see?" --> YOU must enforce at the database layer

The Common AI Security Blind Spot

AI coding assistants regularly produce endpoints vulnerable to Broken Object Level Authorization (BOLA/IDOR):

Four Non-Negotiable Defenses

    AppAuth --> RLS["3. Postgres Row-Level Security: Kernel-level Filter"]

  2. Structural Prompt Delimiters: Wrap untrusted user input inside explicit XML boundary tags (<user_note>...</user_note>) with explicit system instructions prohibiting the model from parsing instructions within those boundaries.
  3. OWASP Top 10 for LLMs: Account for Prompt Injection (LLM01), Insecure Output Handling (LLM02), and Sensitive Information Disclosure (LLM06).
  4. Idempotent Webhook Verification: Verify HMAC signatures on all third-party webhooks (RevenueCat, Clerk), handle duplicate event deliveries idempotently, and check active entitlements at request time.

Domain 3: Cost Engineering & AI Economics (CRITICAL)

A single runaway agent loop or un-cached batch job can exhaust your monthly compute budget overnight.

Three Cost Dimensions

Layer 1: Provider Rates  --- Per-token pricing from model providers
Layer 2: User Workloads  --- Query volume and document sizes per active user
Layer 3: Waste & Retries --- Un-cached system prompts, duplicate worker retries

Practical Cost Levers

  • Prefix Caching: Place static instructions, tool definitions, and few-shot pairs at the start of prompts. Reduces input token billing by 50–90%.
  • Matryoshka Truncation (512d): Reduces vector RAM and indexing overhead by 6x with negligible recall impact.
  • Worker Idempotency Keys: Prevents a restarted NATS worker from re-issuing duplicate embedding API calls for already-processed chunks.
  • Per-User Quotas & Kill-Switches: Enforce daily token caps per user with graceful degradation (HTTP 402 / friendly rate limit messages).

Domain 4: Distributed Systems Mental Models

You do not need to build distributed databases from scratch. You need the vocabulary and failure models to direct AI tooling and make sound architectural tradeoffs.

Messaging Guarantees & Sync Architecture

    subgraph Message_Queues ["NATS JetStream Delivery"]

    end
    subgraph Sync_Engine ["Hybrid Sync Model"]
        PowerSync["PowerSync: LWW at Block Level"]
        Yjs["Yjs CRDT: Character-Level Inside Paragraphs"]
    end

Architectural Tradeoff Summary

  • NATS JetStream: Provides At-Least-Once delivery. If a consumer crashes while generating embeddings, NATS redelivers the message. Your database must enforce a unique constraint on (note_id, chunk_index) to prevent duplicate vector rows.
  • PowerSync + Yjs Hybrid: Last-Write-Wins (LWW) manages coarse block order (fast, simple metadata updates); Yjs CRDT resolves concurrent offline edits within individual text blocks without merge conflicts.

Appendix E: The 10 Priority Things to Learn First

  1. Golden Evaluation Harness: Build a 50-item evaluation set scoring faithfulness and answer relevance.
  2. Postgres Row-Level Security: Enable RLS and verify multi-tenant isolation policies.
  3. Idempotency State Machines: Implement atomic Redis SET NX EX locks for stateful writes and webhooks.
  4. Matryoshka Truncation & HNSW Tuning: Truncate vectors to 512 dimensions and benchmark recall vs. memory.
  5. Prefix Caching Layout: Organize system instructions, tool schemas, and dynamic user inputs for cache hits.
  6. Exponential Backoff with Full Jitter: Eliminate thundering herds during upstream provider degradation.
  7. Transactional Outbox Pattern: Prevent database vs. message broker dual-write hazards.
  8. NATS JetStream Consumer Invariants: Configure explicit acknowledgments (AckWait) and idempotent consumers.
  9. Span-Level Tracing with Langfuse: Instrument async background workers with latency and token cost tracking.
  10. Prompt Delimiter Boundaries: Structure untrusted content inside isolated XML blocks.
